## 수집과 고정된 근거

- 목차: `action=parse&page=<문서명>&prop=tocdata|revid&formatversion=2&format=json`.
- 신화 문단: `action=parse&oldid=<판본ID>&section=<문단번호>&prop=wikitext&formatversion=2&format=json`.
- 최신 API에서는 `prop=sections`가 폐기 예정이므로 `tocdata`를 사용합니다.
- [공식 문단 조회 API](https://www.mediawiki.org/wiki/API:Parsing_wikitext), [접근 정책](https://www.mediawiki.org/wiki/Wikimedia_APIs/Access_policy).
- 실제 사용한 판본·원문 URL·기여자 이력·라이선스·수집 시각·문단 본문은 `public/content/mythology-sources.json`에 저장했습니다.
- 실행 환경의 직접 Node HTTP 요청은 프록시에서 403으로 차단되었습니다. 최초 원문은 사용 가능한 웹 가져오기 도구로 **동일한 실제 Action API URL과 JSON 응답**을 확인해 저장했습니다. 이 경로와 일반 Node 가져오기 스크립트의 실행 범위를 구분합니다.
- 외부의 HTML이나 위키 문법을 앱에 주입하지 않습니다. 스냅샷은 링크·그림·틀 문법을 제거한 텍스트 근거이며, 재생하는 대본은 별도로 편집해 저장합니다.

## 대본과 편집 범위

`src/mythology.ts`의 각 대본은 한국어·영어 18개 문장으로 구성합니다. 같은 문장 배열을 음성·현재 자막·전체 대본에서 공유합니다. 영어는 각색한 한국어 대본의 번역입니다. 한국어는 약 795–800자, 영어는 약 260단어이며, 한국어 340자/분·영어 145단어/분을 가정하면 약 1.8–2.4분입니다. **실제 음성을 측정한 길이가 아니며, 브라우저 음성과 속도에 따라 달라집니다.**

- 오리온: 지정 문단의 아르테미스·아폴론·전갈 전승을 따릅니다. 아폴론이 두 대상을 별자리로 올린다는 해당 판본의 결말을 유지하고, 죽음·독침 등의 구체적인 묘사는 생략했습니다. 서로 다른 계절에 보이는 별자리와 신화의 연결을 실제 추격이나 천체 탄생의 과학으로 설명하지 않습니다.
- 큰곰자리: 지정 문단의 칼리스토·헤라·제우스 전승만 사용합니다. 이 문단에 없는 아르카스 사건을 추가하지 않았습니다. 관계 설명은 어린이에게 맞게 줄였으며, 곰의 모습·가족 대화 질문은 상상 활동임을 분명하게 표현합니다. 같은 문단에 있는 인도의 일곱 현자 전승도 짧게 소개합니다.
- 카시오페이아: 자랑·포세이돈의 분노·안드로메다의 위기·페르세우스의 구출·의자/회전 전승과 관련 별자리의 연결을 따릅니다. 제물과 사슬 등의 구체적 묘사는 생략했습니다. 비교보다 서로의 좋은 점을 찾는 가족 대화 질문을 더했습니다.
- 신화에는 여러 전승이 있음을 알리고, 과학 설명과 구분합니다. 특정 전승을 유일한 정답으로 표시하지 않습니다.
- 검수는 AI 보조 편집을 통한 원문 대조·한영 의미·가족용 표현·추정 길이·공유 대본 구조 확인입니다. **사람의 편집 감수, 전문가·아동 대상 평가, 실제 스피커 음성 청취 검증은 완료하지 않았습니다.** 앱의 검수 범위에도 이 한계를 표시합니다.

## 이후 갱신

일반적인 네트워크 접근이 가능한 Node 24 환경에서 다음을 실행합니다.

```sh
node scripts/import-mythology.mjs
```

환경에서 HTTP 프록시 사용이 필요하면 Node의 지원 범위에 맞게 `NODE_USE_ENV_PROXY=1`을 설정할 수 있습니다. 스크립트는 식별 가능한 User-Agent, 순차 요청, 타임아웃, 최대 재시도·요청 예산을 사용합니다. 접근 제한을 우회하지 않습니다.

**기본 출력은 `docs/content-review/mythology-candidates.json`입니다.** 기존에 검수해 배포한 `public/content/mythology-sources.json`이나 `src/mythology.ts`는 덮어쓰지 않습니다. 후보 판본을 원문·한영 대본과 다시 대조한 뒤 승인된 근거 스냅샷과 대본을 함께 갱신해야 합니다. API 응답이 바뀌거나 실패해도 현재 앱의 검수 대본은 유지됩니다. 앱에서 이야기 버튼을 누를 때마다 외부 API를 재호출하지 않으므로, 페이지를 불러온 뒤에는 저장된 대본으로 감상할 수 있습니다.
